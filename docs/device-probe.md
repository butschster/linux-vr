# Quest 3: результат пробы

Снято 2026-08-06 вехой A на реальном устройстве. Рантайм Oculus **v206.153.0**,
Android 14 (API 34), кодовое имя `eureka`. Рантайм отдаёт 71 расширение.

## Критичное — подтверждено

| Расширение | Версия | Зачем |
|---|---|---|
| `XR_KHR_android_surface_swapchain` | v4 | Android Surface как swapchain: zero-copy `MediaCodec` → компоситор |
| `XR_KHR_composition_layer_cylinder` | v4 | изогнутый слой вместо плоского quad |
| `XR_KHR_opengl_es_enable` | v10 | графический бэкенд |
| `XR_KHR_android_create_instance` | v3 | создание инстанса |

Обе несущие опоры Фазы 2 существуют. Плана Б не потребуется.

## Пределы системы

| | |
|---|---|
| Предел swapchain | 8192×8192 |
| **Слоёв в композиции** | **32** |
| Рекомендовано на глаз | 1680×1760 |
| Максимум на глаз | 8192×8192 |
| Трекинг | ориентационный + позиционный |

**32 слоя** — это снимает главное ограничение Фазы 3. Схема «каждый монитор своим
независимым слоем, со своим разрешением и своей частотой» реализуема без компромиссов;
упрёмся в пропускную способность и энкодер задолго до лимита компоситора.

Рекомендованные 1680×1760 на глаз подтверждают расчёт из README: стримить 4K на
монитор шириной 50° бессмысленно.

## Найденное сверх плана

Проба показала расширения, которые меняют часть решений в лучшую сторону.

### `XR_META_recommended_layer_resolution` v1

Рантайм сам сообщает оптимальное разрешение для слоя с заданным размещением
и угловым размером.

Это **заменяет расчёт через PPD**. Вместо оценки «~25 PPD × 50° ≈ 1250 пикселей»
спрашиваем компоситор и получаем цифру, учитывающую реальную оптику, дисторсию
и текущие настройки. Разрешение виртуального монитора на Ubuntu надо подбирать
под этот ответ, а не под априорную математику.

### `XR_FB_composition_layer_settings` v1

Резкость и суперсэмплинг на уровне слоя. Прямо влияет на читаемость текста —
включить и померить на первом же рабочем слое.

### `XR_FB_swapchain_update_state_android_surface` v1

Смена состояния surface-swapchain на лету. Разрешение слоя можно менять
без пересоздания swapchain — то есть смена разрешения виртуального монитора
не потребует переподключения стрима.

### `XR_META_performance_metrics` v2

Телеметрия компоситора. Даёт замерить последний участок бюджета
(«composition layer → фотоны») изнутри, а не по секундомеру.

### Прочее, пригодится позже

- `XR_FB_composition_layer_alpha_blend` v3 — смешивание с passthrough
- `XR_FB_display_refresh_rate` v1 — смена частоты дисплея на лету
- `XR_FB_android_surface_swapchain_create` v1 — дополнительные флаги создания
- `XR_META_automatic_layer_filter` v1 — автовыбор фильтрации
- `XR_KHR_composition_layer_equirect2` v1 — запасной вариант широкого лейаута
- `XR_META_virtual_keyboard` v1 — системная клавиатура, если понадобится ввод без физической
- `XR_EXT_frame_synthesis`, `XR_FB_space_warp` — для десктопа не нужны, содержимое статично

## Как повторить

```sh
cd client
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb logcat -c
adb shell am start -n dev.butschster.linuxvr/android.app.NativeActivity
adb logcat -d -s linux-vr
```
